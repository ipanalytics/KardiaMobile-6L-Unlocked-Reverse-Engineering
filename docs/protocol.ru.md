# KardiaMobile 6L — справочник по протоколу

Побайтовые заметки, восстановленные из HCI-лога Android и проверенные на живом приборе.

## 1. Расклад GATT

| Handle | UUID | Свойства | Зачем |
| --- | --- | --- | --- |
| — | `ac060001-328c-a28f-9846-5a8aa212661b` | primary service | вендорский сервис, 128 бит |
| — | `ac060002-328c-a28f-9846-5a8aa212661b` | write, indicate | канал управления |
| — | `ac060003-328c-a28f-9846-5a8aa212661b` | notify | поток отсчётов ЭКГ |

Стандартные сервисы (Device Information, Battery, Generic Access) тоже на месте и используются для метаданных ниже, но для самой ЭКГ не нужны.

## 2. Последовательность сессии

```
connect (LE, тип адреса как в рекламе)
  -> бонд: Just Works, шифрование ВКЛ до первой GATT-записи
write  ac060002  "M2 Kfeaa7255122d948f"      (20 байт ASCII, write request)
write  ac060002 CCCD  02 00                   (indications)
write  ac060003 CCCD  01 00                   (notifications)
  <- indication в ac060002: 01
  <- поток notification в ac060003: пары int16 LE, 300 Гц на канал
disconnect
```

Отклонения, замеченные в логе: приложение пишет команду **после** того, как линк зашифрован, и подписывается сразу на оба CCCD, ничего больше не читая. Пропущенный бонд — самая частая причина отказа (`0x0E`).

## 3. Команда разблокировки

20 байт, ASCII:

```
4d 32 20 4b 66 65 61 61 37 32 35 35 31 32 32 64 39 34 38 66
 M  2     K  f  e  a  a  7  2  5  5  1  2  2  d  9  4  8  f
```

Раскладка:

| Байты | Поле |
| --- | --- |
| 0 | `'M'` |
| 1 | цифра режима, `'2'` во всех снятиях (см. ниже) |
| 2 | пробел |
| 3 | `'K'` |
| 4–19 | 16 hex-символов = первые 8 байт `sha256("Triangle" + имя)` |

```
token = sha256(b"Triangle" + advertised_name.encode()).hexdigest()[:16]
command = f"M{mode} K{token}".encode("ascii")
```

`Triangle` — фиксированная строка, а не персональное значение. Имя — то, что прибор печатает в рекламе, например `Kardia6L XXXX`; суффикс — последние четыре hex-цифры его адреса.

Цифра режима во всех снятиях сессии записи 6L была `2`. В вендорских утилитах встречаются другие режимы (прошивка, самотест); проект использует `2` и про остальные ничего не утверждает.

## 4. Поток ЭКГ

- Полезная нагрузка: подряд идущие **int16 little-endian**, вперемешку канал 1 / канал 2.
- Частота: **~300 пар в секунду** (измерено: 2001 уведомление, 18009 пар, 60 с → 300,15 Гц).
- Кадрирование: прибор упаковывает **9 пар = 36 байт**, когда согласованный MTU это позволяет, и **5 пар = 20 байт** на MTU 23. Кадр подрезается под MTU — длина это транспортная деталь, а не константа протокола.
- Неполный хвост: после склейки уведомлений остаток короче 4 байт выбрасывается.

Базовая линия: сырые коды стоят вокруг медленно ползущего смещения (тысячи отсчётов от нуля) и уходят в насыщение (`±26009 ≈ 0x6599`), пока электроды разомкнуты. Смещение надо снять до всего остального:

```
y[i] = x[i] - median(x[i-w : i+w])
```

Оценка пульса, использованная здесь: полосовой фильтр 5–18 Гц, квадрат, скользящее среднее, поиск пиков с рефрактерным окном, затем медиана RR → уд/мин. На записи с хорошим контактом (30 секунд) это устойчиво; на насыщенной или шумной — нет, и честный ответ там «непригодно», а не число.

## 5. Метаданные прибора

Читаются из стандартных сервисов Device Information / Battery во время сессии:

| Поле | Пример | Где |
| --- | --- | --- |
| серийный номер | 13 цифр | `0x2A25` |
| версия прошивки | `3.0.1` | `0x2A26` |
| аппаратная модель | `19SC03.04` | `0x2A27` / `0x2A24` |
| заряд | 85–91 % | `0x2A19` |

Это справочная информация; на путь ЭКГ ничто из этого не влияет.

## 6. Коды ошибок, которые встречались

| Симптом | Что значит | Причина |
| --- | --- | --- |
| `GATT Protocol Error: Unlikely Error (0x0E)` на подписке | линк не зашифрован | нет Just Works-бонда |
| `ATT Error: Insufficient Authentication (0x05)` на чтении | то же | то же |
| рекламы нет вообще | прибор спит | электроды не замкнуты, или соединение держит кто-то другой |
| `Trusted: yes, Paired: no, Bonded: no` | сопряжение сорвано | `bluetoothctl` в batch отправил `quit` раньше, чем `pair` завершился |
